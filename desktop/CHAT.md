# 本地 Ollama 对话版

现在可以输入文字，或点击“开始录音”说话。说完停一下会自动结束录音（也可手动点击），本地 Whisper 将声音转成文字并发送给 Ollama；Ollama 流式回复，已有的瑠璃乃日语音色逐句合成和播放。有 Live2D 模型时，同一个播放通道驱动嘴型；没有模型时也可以先聊天。

**这是按次录音的对话流程，不是持续监听或全双工通话。** 日语音色尚不适合直接合成中文，因此默认支持中文/日语提问、日语回答；回答结束后可额外显示一次本地生成的中文字幕。对话只存在本次程序内存中，不写入聊天记录文件；点击“清空”会移除上下文。模型保留最近 6 轮完整对话。只有你主动保存的称呼和备注会写入 `%LOCALAPPDATA%\RurinoLive2D\memory.json`，可随时编辑或删除。

## Windows 首次准备

1. 确认已装 64 位 Python 3.11 或更新版本（推荐 3.12，包括 Python Launcher；已有就跳过），完整解压程序包，运行 `Install-Windows.cmd` 安装桌宠界面依赖。安装脚本会把过程写入 `install.log`，失败时直接回显最后 20 行。
2. 安装并启动 [Ollama 官方 Windows 版](https://ollama.com/download/windows)。已有聊天模型可直接用；没有则运行 `Install-Chat-Model.cmd` 下载 `qwen3:1.7b`。它只是较小的起步模型，也可以在界面选择自己安装的其他聊天模型。
3. 运行 `Install-Voice-Service.cmd`。此脚本在独立 `.voice-env` 环境安装 CPU 语音运行库，下载并核对仓库中原有的音色权重和日语 BERT（合计约 1.57 GB），并准备 Whisper base 和日语发音词典。原有训练环境不会被修改。已有完整仓库权重时会优先复制复用，否则从本仓库固定提交下载。
4. 运行 `Start-Voice-Service.cmd`，保留这个窗口。首次出现 `Voice model ready.` 表示音色预热已完成。
5. 运行 `Start-Windows.cmd`，点击“和瑠璃乃聊天 · 本地 Ollama”。在聊天窗口点击“检查连接 / 刷新模型”，选择已安装的 Ollama 模型。

依赖与模型首次准备需要联网。对话、语音合成和识别走本机，不使用云端 API，也不需要 API Key。对话客户端仅接受本机回环地址，默认 Ollama 为 `http://127.0.0.1:11434`，语音服务为 `http://127.0.0.1:8765`。

每次使用时保持 Ollama 和语音服务运行，然后启动桌宠。首次没有瑠璃乃 `.moc3` 时，点击导入窗口的聊天按钮即可；已经导入模型时，点击人物或右键菜单进入聊天。

## 操作

- 文字：输入后按 Enter 或“发送”。新的提问会打断上一轮。
- 语音：选择中文、日语或自动识别，点击“开始录音”，说完停顿约 0.9 秒会自动结束并发送；也可以点击“结束并发送”。停顿阈值可选 0.6 / 0.9 / 1.5 秒，取消“说完自动发送”后只保留手动模式。最多录制 30 秒。
- 自动发送的判定依据是录音电平：先用开头约 0.4 秒估计环境噪声，再按说话时长（至少 0.35 秒）和持续停顿判断，因此一声咳嗽不会发送，安静的说话声在安静房间里仍能被识别。噪声很大的环境可能一直判不成停顿，此时手动点击“结束并发送”。
- 中文字幕：默认开启，在日文回复结束后再向本地 Ollama 请求一次翻译，显示为 `〔中文〕…`。它只影响显示，不送进音色模型；关掉它可省掉这次额外推理（本机 RTX 4060 + qwen3:1.7b 短回复实测约 0.1 秒；CPU 或长回复会更久）。译文为空、没有中文或大段保留日文时不会显示，避免贴出错误字幕。
- “记忆…”：填写称呼和少量备注，保存后写入本机 `memory.json`，并从下一条提问起附加到系统提示。留空保存即清空。程序不会自动记录整段聊天。
- “打断”：立即停止播放、取消录音、丢弃本轮尚未播放的语音和迟到的回复。已经在语音服务中执行的推理可能仍会完成，但结果不会再播出来。
- 取消“用现有音色朗读”：停止本轮声音，正在生成的文字继续显示；再次打开朗读从下一轮开始生效。语音服务未启动或地址填写错误时，纯文字聊天仍可使用。
- 桌宠的“静音”只停止本轮语音，文字继续生成；静音期间新回复仍有文字，不启动语音合成。关闭聊天窗口会停止本轮录音和回复。
- 已绑定模型通过 `ParamMouthOpenY` 跟随播放振幅；语音结束、静音或打断后归零。模型网格与自然嘴型仍需 Cubism 绑定。

## 延迟与硬件

本机（i9-13900HX，CPU 推理）实测：预热首次加载约 16.6 秒；新句合成 3.65 秒（约 0.8 秒音频），同句缓存 0.02 秒；本地 Whisper 识别 0.7–0.8 秒。

完整链路分段（真实 Ollama + 真实音色 + 桌宠窗口，播放打桩不发声）：

| 配置 | 首字 | 首句音频 | 整轮 |
| --- | --- | --- | --- |
| CPU 版 PyTorch | 0.02 s | 4.2–6.9 s | 4.6–7.2 s |
| CUDA 版 PyTorch（RTX 4060） | 0.02 s | **0.4–0.7 s** | **0.7–1.0 s** |

纯合成耗时：CPU 3.65 s/句，GPU 平均 0.25 s/句（约 15 倍）。服务重启后的第一次合成有一次性开销（实测 3.9 s，CUDA 初始化），`Start-Voice-Service.cmd` 的 `--warm` 会提前把它付掉。按句合成可以在整段回复完成前开始准备音频，但实际等待还包括 Ollama 生成时间、首次模型加载和队列等待。

语音服务默认自动检测可用的 CUDA，否则选择 CPU；默认安装脚本提供 CPU PyTorch，因此仍会使用 CPU。重复短句使用最多 16 条、16 MiB 的内存缓存，服务重启即清空。首次出现的新句子仍需完整合成。

若 Windows 有支持 CUDA 的 NVIDIA 显卡，把语音环境里的 PyTorch 换成 CUDA 版（本机实测 RTX 4060 + 驱动 560.94，装 `torch==2.3.1+cu121` 后自动选中 cuda）：

```powershell
# 只换 torch 本体，不动其他依赖；若已装过 CPU 版必须加 --force-reinstall
.voice-env\Scripts\python.exe -m pip install --no-deps --force-reinstall torch==2.3.1 --index-url https://download.pytorch.org/whl/cu121
.voice-env\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"
.voice-env\Scripts\python.exe speech\server.py --warm
```

默认脚本装的是 CPU PyTorch，因此只改 `--device cuda` 不会自动获得 GPU 支持，必须换 torch 本体。Ollama 与语音服务会同时占用内存/显存，选模型时应留出余量。语音环境和聊天模型可分别调整，不要升级原训练环境来试错。

## 已验证与未验证

- 真实音色：本机服务使用用户权重成功合成了新的日语句子，不是播放预录问候冒充回复。
- 真实识别：本地 Whisper 将该合成音频正确识别为「今日は何をしていたの？お話を聞かせてね」。这是录音文件测试，不是麦克风硬件验收。
- 自动化：42 项单元测试通过，覆盖协议、模型校验、语音服务缓存、停顿判定与本地记忆；Qt 聊天窗口使用本地协议测试服务验证了流式文字、上下文、分句音频、打断、迟到结果丢弃、录音后发送流程、自动发送（电平序列驱动）、中文字幕、记忆注入、纯文字模式和关闭清理。
- Windows 环境：在本机 64 位 Python 3.11.9 上实际运行了 `Install-Windows.cmd`，脚本正确选择解释器、写入 `install.log` 并完成依赖安装（旧版脚本会因写死 3.12 直接拒绝）。
- Live2D 回归：已有测试模型通过透明渲染、共享播放通道与嘴型归零、拖动、缩放、置顶、重新加载等检查。
- 真实 Ollama：本机（i9-13900HX + RTX 4060 Laptop，16 GB RAM）安装 0.40.11，`qwen3:1.7b` 100% 跑在 GPU。中文提问得到日语回复，首字 1.97 秒（首次加载）、0.05 秒（模型常驻），中文字幕 0.1 秒且译文正确：「你好，今天有点累。」→「今日は疲れたね。どうするか教えて。」→「今天累了。怎么处理呢？」。桌面程序窗口中实测同样通过：检查连接显示「Ollama 已连接」，语音服务未启动时仍能纯文字对话并显示字幕（整轮 2.3 秒，含模型加载）。这是单机短回复数据，不代表长回复和低配机器。
- 真实语音服务：本机 CPU 推理，预录问候与合成音频都走完 TTS→ASR；「おはよう、よく眠れた？」合成后再识别回「おはよう、よく眠れた!」。预录问候被 base 模型识别成「こんにちは、アイテムです。」，说明 base 模型对既有问候有偏差，需要更大模型或人工确认。
- Windows OpenMP 修复：`torch`（MKL）与 `faster-whisper`（CTranslate2）各带一份 `libiomp5md.dll`，第一次调用识别会让整个服务被 `OMP: Error #15` 直接 abort，语音合成一起中断。已在 `speech/server.py` 导入前和 `Start-Voice-Service.cmd` 设置 `KMP_DUPLICATE_LIB_OK=TRUE`；这是 Intel 标注的「不安全」变通（可能崩溃或结果不正确），替代方案（统一 OpenMP 运行库）在 Windows 上更不可控，已在本机确认 TTS 与 ASR 能同进程共存。
- 仍未验收：真人拿麦克风的连续说话、扬声器实际出声、Cubism 绑定后的表情与动作；自动化测试只用电平序列与协议替身，不等于硬件验收。

聊天生成失败后可点击“重试上一条失败的提问”。失败轮不会污染模型上下文。

## 排错

- Ollama 未连接：先打开 Ollama，用 `ollama list` 检查；没有模型先运行 `Install-Chat-Model.cmd`。
- 语音服务未连接：运行 `Start-Voice-Service.cmd`，检查窗口中的报错；纯文字模式可以先用。
- 权重缺失或只是 Git LFS 指针：运行 `Install-Voice-Service.cmd`，下载器会核对文件大小及 SHA-256。不要把指针文件改扩展名当权重。
- 麦克风不可用：检查 Windows“隐私和安全性 → 麦克风”及默认输入设备。程序只在点击开始录音后采集。
- 第一次识别/合成慢：模型或词典尚在加载，先等待语音服务预热；预下载完成后可本地使用。
- 想复用现有语音环境：在装有本文件夹 `speech/requirements.txt` 所需包的独立 Python 环境启动 `speech/server.py --assets 你的完整权重仓库路径`。不要直接运行仓库旧的 `infer_final.py`，它包含另一台电脑的硬编码路径。

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
.venv\Scripts\python.exe tests\smoke_chat.py
```

Qt 测试应在隔离桌面执行；其模拟服务不需要 Ollama，不会向真实设备录音，也不会实际扬声播放。自动发送测试用固定电平序列驱动，不依赖麦克风硬件。Windows 端仍需做一次真实“录音 → Ollama → 用户音色 → 播放”的验收。

记忆与设置文件都在 `%LOCALAPPDATA%\RurinoLive2D\`：`memory.json` 可编辑，`desktop.log` 记录运行日志，删除整个目录即可恢复默认。
