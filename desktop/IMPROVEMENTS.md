# 改进清单

## v0.2.1 已完成

- 取消朗读、桌宠静音只停止语音，不再截断正在生成的文字；重新打开朗读也不会播放已取消的旧句子。
- 纯文字模式不再要求语音服务地址正确。检查连接时，聊天与语音分别检查，互不阻塞结果展示。
- 聊天失败后可点击“重试上一条失败的提问”，保留原提问；失败轮不写入模型上下文，清空对话也会清除重试内容。
- 语音服务显示尚未加载、加载/预热中、就绪、合成中或失败。只有第一次真实合成成功后才报告音色已加载。
- 同一服务进程缓存最近的相同短句，最多 16 条且总量不超过 16 MiB，重启即清除。缓存键为完整句子，合成参数和模型在服务运行期间固定。
- 语音服务默认自动检测当前 PyTorch 是否能使用 CUDA；不可用则用 CPU。默认安装仍为 CPU PyTorch，需要另行安装兼容 CUDA 版本才能使用 NVIDIA GPU。

验证：16 项单元测试、Qt 聊天回归、真实 Live2D 测试模型回归通过。真实音色「おかえり。」生成 0.766 秒音频，首次请求约 7.36 秒，第二次缓存命中约 0.02 秒，两次 WAV 的 SHA-256 一致。该数据不代表新句子的合成速度，也未计入 Ollama 回复时间。Windows、实际 Ollama 和 GPU 尚待目标机器验收。

## 建议下一步按此顺序推进

| 优先级 | 改进 | 具体结果与验收方式 |
| --- | --- | --- |
| 1 | Windows 真实全链路与延迟优化 | 用真实麦克风、Ollama、用户音色、扬声器连续对话 10 轮，记录识别、首字、首句音频各段耗时，再根据显卡选择 GPU 语音推理和聊天模型大小。不要用缓存命中的速度替代新回复延迟。 |
| 2 | 完成瑠璃乃 Cubism 绑定 | 先做眨眼、嘴型、呼吸、轻微歪头与发梢摆动；验证转头加闭眼、歪头加张嘴等组合无裂缝，再添加挥手。保留已确认的形象。 |
| 3 | 说完自动发送 | 增加可开关的语音活动检测，用可调的停顿时间结束录音；用短暂停顿、空白音频和背景噪声测试，保留手动结束按钮。 |
| 4 | 日语语音与中文字幕 | 保留日语原句用于当前音色合成，另外显示中文翻译。中文翻译不能误送给仅支持日语的音色模型。 |
| 5 | 可编辑的本地记忆 | 由用户主动保存称呼、偏好等少量资料，界面能查看、修改、删除；不默认永久保存整段聊天。 |
| 6 | 表情与对话状态联动 | 有真实绑定模型后，让倾听、思考、开心等状态使用对应表情和小动作，避免随机大幅摆动影响角色形象。 |

目前最值得投入的是第 1、2 项：让对话真正顺畅，并让确认过的角色自然动起来。其余功能在这两项验收后再增加。
