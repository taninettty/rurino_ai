# 改进清单

## v0.3 已完成（对话体验）

- **说完自动发送**：录音时按 50 ms 一帧计算电平，开头约 0.4 秒估计环境噪声，之后按“说话至少 0.35 秒 + 持续停顿”判断结束。停顿阈值可切 0.6 / 0.9 / 1.5 秒，可整体关闭；手动“结束并发送”和 30 秒上限始终保留。电平只用于判定，不改变写出的 WAV。
- **中文字幕**：日文回复结束后，再向本地 Ollama 发一次非流式翻译请求，结果显示为 `〔中文〕…`。译文不会送进音色模型；为空、没有中文或大段保留日文时拒绝显示，避免贴出错误字幕。可关掉以省一次推理。
- **可编辑本地记忆**：称呼 + 最多 20 条备注（每条 120 字内），保存到 `%LOCALAPPDATA%\RurinoLive2D\memory.json`，原子写入、可手工编辑删除；损坏文件回退为空而不是崩溃。只在下一条提问起附加到系统提示，不记录整段聊天。
- **Windows 可用性**：安装脚本不再写死 `py -3.12`，改为依次尝试 3.12 / 3.13 / 3.11 并要求 64 位（`live2d-py` 提供 `cp311-abi3` 轮子）；安装过程写入 `install.log` / `voice-install.log`，失败时回显最后 20 行。
- **语音服务在 Windows 直接崩溃**：第一次用麦克风时 `torch` 与 `faster-whisper` 的 `libiomp5md.dll` 冲突触发 `OMP: Error #15`，整个语音服务退出（TTS 一起死）。已在导入前设置 `KMP_DUPLICATE_LIB_OK`，并在实测中确认 TTS 与 ASR 能同进程共存。
- **测试在 Windows 变红**：符号链接逃逸用例在无开发者模式、`os.symlink` 无权限时不再报错，仍断言越界路径被拒绝。

验证：42 项单元测试通过；Qt 聊天流程（`tests/smoke_chat.py`）在新增用例下通过，覆盖电平驱动的自动发送、字幕请求、记忆进入系统提示；`Install-Windows.cmd` 在仅有 Python 3.11.9 的 Windows 上实机跑通；真实 Ollama（`qwen3:1.7b`，RTX 4060 GPU）实测首字 0.05 秒、字幕 0.1 秒且译文正确。真实麦克风输入与语音服务耗时仍待验收。

## v0.2.1 已完成

- 取消朗读、桌宠静音只停止语音，不再截断正在生成的文字；重新打开朗读也不会播放已取消的旧句子。
- 纯文字模式不再要求语音服务地址正确。检查连接时，聊天与语音分别检查，互不阻塞结果展示。
- 聊天失败后可点击“重试上一条失败的提问”，保留原提问；失败轮不写入模型上下文，清空对话也会清除重试内容。
- 语音服务显示尚未加载、加载/预热中、就绪、合成中或失败。只有第一次真实合成成功后才报告音色已加载。
- 同一服务进程缓存最近的相同短句，最多 16 条且总量不超过 16 MiB，重启即清除。缓存键为完整句子，合成参数和模型在服务运行期间固定。
- 语音服务默认自动检测当前 PyTorch 是否能使用 CUDA；不可用则用 CPU。默认安装仍为 CPU PyTorch，需要另行安装兼容 CUDA 版本才能使用 NVIDIA GPU。

验证：16 项单元测试、Qt 聊天回归、真实 Live2D 测试模型回归通过。真实音色「おかえり。」生成 0.766 秒音频，首次请求约 7.36 秒，第二次缓存命中约 0.02 秒，两次 WAV 的 SHA-256 一致。该数据不代表新句子的合成速度，也未计入 Ollama 回复时间。

## 建议下一步按此顺序推进

| 优先级 | 改进 | 具体结果与验收方式 |
| --- | --- | --- |
| 1 | Windows 真实全链路与延迟优化 | **已测到分段并解决瓶颈**：CPU 合成 3.65 s/句、整轮 4.6–7.2 s；换 CUDA 版 PyTorch 后 0.25 s/句、整轮 0.7–1.0 s（i9-13900HX + RTX 4060）。首字 0.02 s，字幕 0.1 s。仍需补真人麦克风连续 10 轮的识别耗时。 |
| 2 | 完成瑠璃乃 Cubism 绑定 | 先做眨眼、嘴型、呼吸、轻微歪头与发梢摆动；验证转头加闭眼、歪头加张嘴等组合无裂缝，再添加挥手。保留已确认的形象。 |
| 3 | 字幕与播放同步（可选） | 当前字幕在整段回复结束后才出现；若要“听到哪句看到哪句”，需要把翻译也改成按句请求，并处理乱序返回。 |
| 4 | 表情与对话状态联动 | 有真实绑定模型后，让倾听、思考、开心等状态使用对应表情和小动作，避免随机大幅摆动影响角色形象。 |

目前最值得投入的是第 1、2 项：让对话真正顺畅，并让确认过的角色自然动起来。
